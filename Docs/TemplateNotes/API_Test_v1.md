# API_Test_v1 and API_EssentialTests_v1

With `ApiAuth=true` the fixture sets a signing key and an administrator made for the run (random values, nothing saved), signs in once and gives every test a client with the token; `ApiFixture.Anonymous()` is a client without one, each table has a test that its list answers 401 without a token, and `AuthApiTests` covers a wrong password (401) and a blank name (400).

An integration test class per table (`<Table>ApiTests.cs`) and the test project around them. `ApiTests=true` in the project file adds both to a whole-project run (or name `API_Test` in `PlanAlso` and run the `Tests` essentials group). The files go to their own project folder, `OutputApiTests` (default `<ProjectName>.Api.Tests`), beside the API; the template config says `OutputRoot=ApiTests`.

- **What a class tests:** a row is added (201), read (200), changed (200, read back) and removed (a 404 afterwards); a row that is not there answers 404; the search answers a page and sorts by every column it offers (a name it does not offer, even `x' OR 1=1`, is ignored); a table the API can clone (`CloneShape`) clones a row (201, a new key); a table with a unique index on one free text column refuses a second row with the same value (a 4xx, never a 500 and never saved); and with `ApiValidation=true` a text longer than its column and an integer past its CHECK range answer 400. The row is removed in a `finally`, so a failed run leaves nothing behind.
- **Bodies:** the same columns and example values as `API_Http` (`ApiSampleValues` in Core). A free text column gets a unique ending (`ApiFixture.Unique`), so a unique index does not stop a second run; an email, phone or URL column and a CHECK-list column keep their fixed value. A foreign key (a number, text or a guid) takes the key of the first row of the parent's list route (`ApiFixture.ExistingKeyAsync` / `ExistingCodeAsync`); a parent without a list route (an enum) gets the sample value. A parent with no rows is filled by the test: the fixture adds one with the body the parent's own test class builds (`<Parent>ApiTests.NewBodyAsync`, found by name), which seeds that parent's own parents the same way, so a chain fills itself in order; the rows added are deleted again when the run ends (a row something still points at stays). Only a parent with no test class of its own (a name/active table) or one that refuses the body (its answer is in the message) leaves the test inconclusive. A key the database does not number gets a random one.
- **The changed column** is the first free text column, else a bit column, else a whole number with room to go up by one; a table with none of them skips the change step.
- **Which tables:** the ones `API_Crud` writes an API for, whatever the key (`TableModel.HasCrudApiOfAnyKey`); any other table is refused with the reason. A text key is made by the test (`ApiFixture.NewCode(length)`, random capitals and digits, since the person chooses it), a uniqueidentifier by `Guid.NewGuid()`; the id is read as text and put in the route with `Uri.EscapeDataString`, and the 404 test asks for a key no row has (`~~~`, a new GUID, `int.MaxValue`). A text foreign key to a text-key parent takes the key of the parent's first row (`ApiFixture.ExistingCodeAsync`). `ApiFixture` is in the Tests essentials group, written once: a project made before this needs `--replace` to get `NewCode` and `ExistingCodeAsync`.
- **The test project** (`API_EssentialTests`, essentials group `Tests`, written only with `ApiTests=true`): MSTest 4, `Microsoft.AspNetCore.Mvc.Testing`, a project reference to the API, `GlobalUsings.cs` and `ApiFixture.cs`. The API's `Program` is made `public partial` (the `Program.cs` of `API_EssentialProgram`) so `WebApplicationFactory<Program>` can start it in process. The API project itself gets no new package.
- **The database is a scratch copy.** SQLite: the fixture copies the database file (`DatabaseName`, relative to the API folder or absolute) to a temporary file and points the API at the copy; the original is never opened for writing. Every other database: set `<PROJECT>_TEST_CONNECTION` (the project name in capitals, other characters as `_`) to the connection string of a scratch copy; without it each test reports itself inconclusive. The fixture also raises the production profile's rate limit so a test run is not throttled.
- **Running:** `dotnet test` in the test folder, or `codegen generate --test`, which runs `dotnet test` on the test project when `ApiTests=true` and `TestApi` says nothing.
- **Run on SQL Server:** the InvoiceSystem sample's 211 tests pass over a scratch copy of the database (`INVOICESYSTEM_TEST_CONNECTION`). They found that every generated procedure had been applied with `QUOTED_IDENTIFIER OFF` (`sqlcmd` defaults to off), which makes a clone fail on a table with a filtered or computed-column index: apply the scripts with `sqlcmd -I` (see `SP_Clone_v1.md`).
- **Parent rows:** the InvoiceSystem SQLite sample emptied of every row ran 182 tests with none skipped (switching the seeding off skips 12 of them), and a run against a kept copy left every table empty again.
- **Not done:** Testcontainers (a container per run, a package), a delete of a row another row uses (the model does not know the foreign key's delete rule, and a cascading key would remove the child), the junction endpoints, and the same for PostgreSQL and MySQL; all are held for a later round.

**Roles:** with `ApiAuth` and a read or write rule for the table, the class has tests that a role the rule does not list is refused (403 `role-not-allowed`, before the row is looked for) and, when the rule lists another role and the table is not owned, that the listed role may read or add. `ApiFixture.ClientInRole(role)` signs a token of that role with the key of the run, so no user has to exist; a project made before needs `--replace` of the Tests essentials.

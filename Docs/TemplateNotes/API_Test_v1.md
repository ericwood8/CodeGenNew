# API_Test_v1 and API_EssentialTests_v1

An integration test class per table (`<Table>ApiTests.cs`) and the test project around them. `ApiTests=true` in the project file adds both to a whole-project run (or name `API_Test` in `PlanAlso` and run the `Tests` essentials group). The files go to their own project folder, `OutputApiTests` (default `<ProjectName>.Api.Tests`), beside the API; the template config says `OutputRoot=ApiTests`.

- **What a class tests:** a row is added (201), read (200), changed (200, read back) and removed (a 404 afterwards); a row that is not there answers 404; the search answers a page; and with `ApiValidation=true` a text longer than its column and an integer past its CHECK range answer 400. The row is removed in a `finally`, so a failed run leaves nothing behind.
- **Bodies:** the same columns and example values as `API_Http` (`ApiSampleValues` in Core). A free text column gets a unique ending (`ApiFixture.Unique`), so a unique index does not stop a second run; an email, phone or URL column and a CHECK-list column keep their fixed value. A foreign key takes the key of the first row of the parent's list route (`ApiFixture.ExistingKeyAsync`); a parent without a list route (an enum, a name/active table) gets the sample value, and a parent with no rows makes the test inconclusive. A key the database does not number gets a random one.
- **The changed column** is the first free text column, else a bit column, else a whole number with room to go up by one; a table with none of them skips the change step.
- **Which tables:** the ones `API_Crud` writes an API for (`TableModel.HasCrudApi`); any other table is refused with the reason.
- **The test project** (`API_EssentialTests`, essentials group `Tests`, written only with `ApiTests=true`): MSTest 4, `Microsoft.AspNetCore.Mvc.Testing`, a project reference to the API, `GlobalUsings.cs` and `ApiFixture.cs`. The API's `Program` is made `public partial` (the `Program.cs` of `API_EssentialProgram`) so `WebApplicationFactory<Program>` can start it in process. The API project itself gets no new package.
- **The database is a scratch copy.** SQLite: the fixture copies the database file (`DatabaseName`, relative to the API folder or absolute) to a temporary file and points the API at the copy; the original is never opened for writing. Every other database: set `<PROJECT>_TEST_CONNECTION` (the project name in capitals, other characters as `_`) to the connection string of a scratch copy; without it each test reports itself inconclusive. The fixture also raises the production profile's rate limit so a test run is not throttled.
- **Running:** `dotnet test` in the test folder, or `codegen generate --test`, which runs `dotnet test` on the test project when `ApiTests=true` and `TestApi` says nothing.
- **Not done:** Testcontainers (a container per run, a package) and a seed step for a scratch database that has no parent rows; both are held for a later round.

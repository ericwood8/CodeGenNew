# UNO_Test_v1 and UNO_EssentialTests_v1

MSTest tests of the view models the Uno dialogs are written with, in a test project beside the Uno app. `DesktopTests=true` in the project file adds both to a whole-project run (or name `UNO_Test` in `PlanAlso` and run the `Tests` essentials group of the Uno stack). The files go to `OutputUnoTests` (default `<ProjectName>.Uno.Tests`); the template config says `OutputRoot=UnoTests`. `codegen generate --test` runs `dotnet test` on that project when `DesktopTests=true` and `TestUno` says nothing.

- **The project is a plain `net10.0` one** (`UNO_EssentialTests`, essentials group `Tests`, written only with `DesktopTests=true`): it compiles the app's own files as linked files (ViewModels, Models and Services), so the tests run on any machine with the .NET SDK, with no window, no WinUI and no device. Two platform types a view model touches are small stand-ins in `PlatformShims.cs` (`Visibility` and the WinRT `CurrencyFormatter`), so the tests do not judge how a number is shown in a grid.
- **`FakeApi` is the `HttpMessageHandler` behind the app's `ApiClients`. A list, a lookup and the guards answer with nothing, a create echoes its body, an update and a delete answer 204, every write is kept in `Writes`, and `FailWrites(status)` and `Unreachable()` make it refuse. With `Auth=true` the clients get an `AuthSession`.**
- **What a class tests** (`<Table>DetailViewModelTests.cs`, or `<Table>DetailMasterViewModelTests.cs` for a table with child tables), over a stand-in for the API: a new row with nothing filled in is refused with the first required field's sentence; a row opened and saved unchanged is saved with every value it had; and each rule the form has refuses a spoiled value after a valid row was opened: a text shape (email, phone, web address, ...), a date later than today (`NotFutureDateColumns`), an end date before its start (`DatePairs`), a number that is not whole. The Uno classes also check that the dialog shows "Some of the values are not acceptable!" when the API refuses the save and "The server could not be reached." when it cannot be reached.
- **Where the cases come from:** `DesktopTestPlan` in Core decides them from the rules `DesktopFormCode` writes the view model from, and `DesktopTestCode` writes the class, so WinUI3 and Uno test the same things. The row is made from the same sample values as the API tests (`ApiSampleValues`).
- **Not tested:** how the dialog looks, the child grids' sorting, the typed key (a new row's key box is open and an existing row's is locked), the guards and the editable child rows' lines; a dialog is still checked by driving the app.

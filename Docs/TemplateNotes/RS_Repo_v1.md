# RS_Repo_v1

`src/repos/<table>.rs`: the statements of a table and the functions that run them with sqlx.

- **Fixed text, no routine.** Every statement is a constant written for the database that was read: the quotes, the positional placeholders (`$1` for PostgreSQL, `?` for MySQL and SQLite), the casts PostgreSQL needs for `money` (read as `numeric`, written as `$n::numeric::money`) and for an enum column (read and written as text), `RETURNING` where the database has it (PostgreSQL, SQLite) and a second read of the row by its key where it has not (MySQL, through `last_insert_id`). SQLite reads a decimal as `CAST(col AS REAL)`, because it stores a whole number written to a DECIMAL column as an integer and sqlx refuses to read an integer as a double. sqlx 0.9 accepts only literal SQL, so nothing is assembled at run time except the search's WHERE.
- **Functions:** `get_all`, `get_by_id`, `insert`, `update`, `delete` and, for a cloneable table (`CloneShape`), `clone_row`: one `INSERT ... SELECT` that copies the row, sets the create date, leaves the modify and inactivation columns empty, and gives a unique text column a free value (`suggest_<column>`: the value, then with 2, 3 ... after it), the rules `SP_Clone` and `CloneEf` follow.
- **Search** (a table with a search endpoint): `SearchQuery` (one optional filter per searchable text column, `pageNumber`, `pageSize`, `sortBy`, `sortDir`, with the names the front ends send), `sort_expression` (a `match` over the fixed sort list; a foreign key sorts by its parent's display text through a subselect; an unknown name gives the default order) and `search`, which builds the WHERE with sqlx's `QueryBuilder`, binding every value. A filter is "contains, ignoring case" (`ILIKE` on PostgreSQL), and `%` and `_` in the value are ordinary characters (`escape_like`; MySQL needs the escape character written twice, `DialectInfo.ContainsParts` knows).
- All the SQL comes from `RustTable` in Core, which reads `SearchPlan`, `SearchSort`, `CloneShape` and `DialectInfo`, so a Rust dashboard or a Rust UI would read the same plan.
- **Checked** on all three databases with `Test-ApiCrud.ps1` (create, read, update, list, delete), `Test-OpenApiRoutes.ps1` (every path of the OpenAPI document answers and every schema property is in the JSON), and by hand: clone, search with `%` in the value, a sort by a foreign key, a delete of a row in use (400), an enum and a money column round trip.
- **Not done:** junction (many-to-many) endpoints, a Rust `AccessMode` setting (a Rust API never uses routines), and caching.

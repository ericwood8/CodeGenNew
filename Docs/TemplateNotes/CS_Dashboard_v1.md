# CS_Dashboard_v1

`DashboardData.cs`: the dashboard's data for the whole database, written only for a project with `Dashboard=true`. It holds the widgets `DashboardPlan` (Core) chose, each with its one fixed SQL statement, and `LoadAsync(context, table?, useCache?)`, which runs them through the context with `Database.SqlQueryRaw<T>` and returns every widget's points (or rows). The web API (`API_Dashboard`) and the desktop page (`WinUI3_DashboardPage`) both call it, so they show the same numbers; the file goes into the `Repositories` folder of the `Api` and `WinUI3` stacks.

- **The choice is made once, in Core.** `DashboardPlan.Build(database, project)` reads the schema's own facts and ranks the candidates: a table's row count, a money column (total, average, largest) and its sum by a foreign key's display name (the ten largest), a count per value of a CHECK-list column or of a small lookup table (2 to 12 rows), a monthly trend over a date column (the newest twelve months of the data, measured from the table's latest date), active against inactive rows (or live against soft-deleted), rows current, expired or not started by their start and end dates, a master's count beside its child's, and the latest ten rows. The page shows at most four cards (two of them sums of money), two top lists, two breakdowns, two trends and one recent list. A money column whose name says a limit, a rate, a percentage, a factor or a quantity is never a measure, and a tax or fee is ranked far below a total, a balance or an amount. `Dashboard.md` (`MD_Dashboard`) lists the choice and what the caps left out.
- **One statement per widget, no parameter.** The statements are written with `DialectInfo` (quotes, paging, date arithmetic, casts), so they run on SQL Server, PostgreSQL, MySQL and SQLite, in `AccessMode=Routines` and in `Ef` alike. Every number is cast to a double, and PostgreSQL's `money` (which has no average) is cast to `numeric` first. A table named by the caller (`?table=`) is only compared with the fixed list; no text from outside reaches a statement.
- **`DashboardMeasures`** adds or replaces a widget: `Table.Column:sum|avg|max|min|count` is a card, `Table.Column:sum:DateColumn:day|month|year` a trend. A measure that names a table or column that does not exist stops the run with the text of the setting. **`NoDashboardTables`** leaves a table out.
- **Caching:** with `useCache` the answer is kept for a minute per table (the web API passes true; the desktop page does not, so Refresh reads the database).
- **Not done:** counts are `COUNT(*)`, not the catalogue estimate, so a table of many millions of rows makes its card slow; trends read the date column as it is, so an unindexed one scans the table.
- **Checked** on the InvoiceSystem copies of all four databases: every statement was run by hand (`DashboardQueries.sql`) and through the generated API; the values agree (SQL Server's `money` keeps four decimals, the others two). The suite runs every statement on a SQLite file and compares the numbers with the rows added up by hand.

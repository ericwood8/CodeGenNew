# API_OpenApi_v1

One OpenAPI 3.0 document (`openapi.yaml`) for the whole database, written from the schema by the same rules the API templates use.

- **Paths:** for every table `API_Crud` writes an API for (a single int, uniqueidentifier or text key, not an enum or a name/active table; the `{id}` parameter is an integer, a string, or a string of format uuid by the key): `GET` and `POST /api/<plural>`, `GET`, `PUT` and `DELETE /api/<plural>/{id}`, `POST /api/<plural>/{id}/clone` where the clone routine exists, and `GET /api/<plural>/search` where `API_Search` writes one (an optional query parameter per searchable column, `pageNumber`, `pageSize`, `sortBy`, `sortDir`; the result is a `<Table>SearchResult` of `items`, `page`, `pageSize`, `totalCount`, `totalPages`). The plural is the one `Pluralizer` gives (a word that already ends in `s` stays as it is: `/api/customerstatus`).
- **Schemas:** one per table. Property names are ASP.NET Core's camel casing (`JsonNames.Camel`); `type` and `format` from the column type (a date is `date-time`, a decimal a `number`); `nullable`; `maxLength` (a Unicode column's byte length halved); `minimum` / `maximum` from the name rules (a month, a percentage) and the database's CHECK ranges, with `exclusiveMinimum` for a strict bound; `enum` from a CHECK list; `required` for every column that cannot be NULL; an optional property for each single-column foreign key's parent (the entity's navigation property).
- **Server:** `http://localhost:<ApiPort>` (the project setting, 5080 by default). Not described: authentication, a table the API templates skip.
- **Use:** feed it to Kiota, NSwag or openapi-generator for a client in another language, or to a Swagger UI.
- **Not in a plan** unless the project names it in `PlanAlso`. Run it again when a table or an API template changes: the routes follow the API templates by rule, not by reading the running API.
- **Checked:** the document of the PostgreSQL sample is valid for `Microsoft.OpenApi.Readers` (24 paths, 13 schemas), every GET path answered 200 on the running sample API and every `PUT /{id}` answered 400 (the route exists), and the schema's property names equal the JSON keys the API sends. The SQL Server and MySQL samples generate the same way.
- **Descriptions:** a table's description and a column's description (what the database holds: SQL Server `MS_Description`, PostgreSQL `COMMENT ON`, MySQL `COMMENT`) become `description` of the schema and of the property.
- **Served by the API:** `ApiDocs=true` adds this template to a plan and makes the API essentials write `OpenApiDocs.cs` (`app.MapOpenApiDocs()` serves `/openapi.yaml` and a Swagger UI page at `/docs`, Swagger UI loaded from a CDN) and a `<Content Include="openapi.yaml">` line in the project file.
- **Checked by `Docs/Verification/Test-OpenApiRoutes.ps1`:** every documented GET answers 200 on the running API (apply the generated SQL first), every `PUT /{id}` 400, and the schema's properties are in the JSON of a real row; and on a generated project `/docs` answered 200 as HTML and `/openapi.yaml` as YAML.

# UNO_DetailMasterScreen_v1

The Uno twin of `WinUI3_DetailMasterScreen` (see `WinUI3_DetailMasterScreen_v1.md`): `Views/<Table>DetailMasterDialog.xaml` and `.xaml.cs`, `ViewModels/<Table>DetailMasterViewModel.cs` (`PaginationBar` and `CurrencyNumberFormatter` come from the `Controls` essentials group, `UNO_EssentialControls`). It is `UNO_DetailScreen`'s dialog (same fields, drop-downs and checks) with one sortable grid per child table under the form, so editing a row also shows the rows that hang off it.

The child rows come from the child's API client: `GetAllAsync()` of the child table, filtered in the view model to the rows whose foreign key is this row's key (the Blazor page reads them the same way). The columns are the model class's properties (`typeof(<Child>).GetProperties()`), without the columns `ChildGrid` hides (the child's own key and the link back, ids that have no display name, row versions) and without long text; a foreign key with a display name shows the parent's name (`GetLookupAsync()`, or only the keys the rows show for a parent with too many rows) and gets a filter drop-down. A header click sorts the rows (again: flips the direction; kept between runs by `GridSortStore`), a right-click on the grid offers Clear sort.

A row of a child grid has Edit and Delete. Edit hides this dialog and opens the child's own dialog (`<Child>DetailMasterDialog` when the child has children itself, else `<Child>DetailDialog`); this dialog is not reopened afterwards (only one `ContentDialog` can be open, and reopening from a nested drill-down crashes WinUI 3). Delete asks to be pressed twice ("Confirm?"); the API's refusal (a 400) shows "It cannot be deleted because it is in use!".

A table gets this dialog when `DatabaseModel.IsDetailMaster` says so (the project's `DetailMasterTables`, else every table with a child table); a child that has no screen of its own (not in `Screens`) leaves the Edit button with no dialog to open, so list the children in `Screens`. A child with a composite key, or a name / active child, has no grid. The page takes `ApiClients`; there is no EF context. See `UNO_Screens_v1.md`.

With `EditableChildren` a child that the web rule allows (`EditableChild`) and whose columns the boxes can hold is not a grid: its rows are a table of boxes inside the dialog (a text box, a number or money box, a date picker, a check box, a list of choices, a drop-down or type-ahead box for a parent), with Remove on each line and an Add button. The text of the row class, the lists and the panel is Core `DesktopEditRows`, written to `Views/<Table>DetailMasterEditRows.cs` and the same on WinUI3 and Uno. A line is checked before anything is saved, and the first one that is wrong stops the whole save with a sentence naming its row. A name / active parent, a child with a binary column or a child listed only as a name that points at several tables keeps its read-only grid. Rows can be added while the parent is new.

Uno sends the row and the lines in one request (`CreateAsync` / `UpdateAsync` with a `children` dictionary, written by `UNO_Client`), which the API reconciles as for the web stacks.

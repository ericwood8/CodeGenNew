# BLZ_Page_v1

`Pages/<Table>Page.razor`: the Blazor counterpart of `TSX_Page`. The route is the screen's route (`ScreenNames.Route`), the same one `BLZ_Screens` puts in the menu.

- **Grid:** the columns `ForGrid` picks (never a long text column at first; the Columns list can show one, cut short), a header button that sorts for each sortable column (an arrow shows the direction), 20 rows a page with Previous / Next and a "Rows per page" box (10, 20, 50, 100), "Nothing found." when a loaded page has no rows, a page past the end (the last row of the last page was deleted) that falls back to the last page there is, Edit, Clone and Delete buttons per row.
- **Search:** a box per searchable column, Search and Clear; the sort is kept while paging and searching.
- **Form:** a panel over the page with an `EditForm`. `InputText` (`InputTextArea` for a column of 100 characters or more), `InputNumber`, `InputDate`, `InputCheckbox`, an `InputSelect` of the parent's display column for a foreign key, and of the listed values for a column that has choices. A required column carries `required`. Add New starts date columns at today and yes / no columns at their default.
- **Errors:** a failed load, save, delete or clone shows a sentence (`ApiException.Explain`); deleting a row that is in use says so.

A text key (a country or currency code) is the first field and a grid column: an `InputText` that is typed on a new row and `readonly` on an existing one (the page already keeps `isNew`); a duplicate key (409) says "A country with this alpha3 code already exists!". A drop-down over a text-key parent holds codes and starts on a blank "Select" (`value=""`).

The row being edited is a copy (`ApiSupport.Copy`), so Cancel leaves the grid as it was. Limits are in `BLZ_Screens_v1.md`.

## Credentials and long text

A text column named like a credential (`ColumnModel.IsCredentialColumn`: a name with `Password` in it, or ending in `Salt`, `Secret`, `ApiKey` or `Token`) is in neither the grid, the form nor the search bar. A row that is edited keeps the value it was read with. A grid that would show fewer than `GridColumns.MinColumns` (3) columns because its text is 100 characters or longer is filled up with the first of those columns.

## Stamps, money, short boxes, bold buttons

A column the system writes (`ColumnModel.IsSystemStampColumn`: CreateDate, CreateUser, ModifiedDate, ModifiedBy, LastDateChanged) is a label with the value once the row exists, never a box, and its timestamp is not cut to a date when the row is opened. A money column (a money type, or a decimal, float or real whose name has a Fee, Balance, Amount, Surcharge, Upcharge, Discount, Price, Total, Average, Tax, Cost or Rate word and no percent, quantity, hours or ratio word) is edited in a money box showing $1,234.50 (React `CurrencyInput`, Angular `appCurrency`; WinUI3 already had a currency NumberBox) and the grid shows at least two decimals. A whole number with short values (a month, a year, a tinyint) gets a short box (`ProjectSettings.NumberBoxCharacters`). Every button's caption is bold (the Styles / Layout / App essentials: refresh them with `--replace`). An editable child with more than six columns is one block of labelled fields per row (`EditableChild.UsesCards`).

**Money box and child grids.** A money column that is not a foreign key, a list of choices or a stamp is edited in `CurrencyInput` (`Components/CurrencyInput.razor`, written by the Support essentials; it shows `$1,234.50` when not being edited and the plain number while it is, and refuses text with "Enter an amount."), and the form carries a `ValidationSummary` so that message shows. A table with child tables shows one read-only grid per child under the form while a row is edited (not while one is added): the whole child table is read through its client and filtered by the row's key, as the React page does; the child's own foreign keys to tables with a display column show that name; `ChildGridTitles` names the grid. Each child row has Edit (opens the child's own page on that row with `?edit=<id>&back=<this page>`; saving or cancelling there returns here with this row open again; left out when the project's `Screens` omits the child) and Delete (confirm, then the child client's delete). Every page honours `?edit=` and `?back=`. A child the project lists in `EditableChildren` is not a grid under the form: its rows are a table of boxes inside the form (also while a row is added), with Add and Remove, saved with the row in one request (`<Type>Client.CreateAsync(row, children)` / `UpdateAsync(id, row, children)`, the lists under `departmentTeams` and the like; the API makes the child table match). Each cell is the box its column needs (a drop-down of the parent for a foreign key, a type-ahead for a big parent, a money box, a date, a check box, a list of choices); a new row starts with today in a date and the database default in a yes / no. A child with more than six columns scrolls sideways (React and Angular write a block per row). A tinyint column is a `short` in the model, because `InputNumber` has no `byte`. Existing projects need `essentials --stack blazor --replace` (or `REPLACE=1`) only if they already have a `CurrencyInput.razor`.

## Required fields

A required field (NOT NULL, other than a yes/no box and the stamps the system writes; `FormModel.IsRequired`) gets the native `required` attribute and, unless `RequiredMarks=false`, a red `*` written after its caption: `<span aria-hidden="true" style=...>*</span>`. Screen readers skip the mark because the field itself says it is required. There is no legend line. Save is not disabled; the browser refuses an incomplete submit as before.

## Sign-in, role rules and OData

- **`Auth=true`:** every page carries `@attribute [Authorize]`, with `Roles = "Administrator,Hr"` for a table with `ReadRoles` or `TableReadRoles` (an address typed for a page the role may not read goes to the start page). With `WriteRoles` or `TableWriteRoles` for the table, Add New, Edit, Clone and Delete show only to the roles that may write (`CanWrite`, from `AuthSession.HasRole`), a `?edit=` address opens no form for another role, and a child grid's Delete follows the child table's write roles. See `BLZ_EssentialAuth_v1.md`.
- **`BLZ_ODataPage`** is this template run with `Variant=OData` (its config says `Base=BLZ_Page_v1.tt`): the same page over the table's OData client, with several sorts and a filter row; see `BLZ_ODataPage_v1.md`. With `ODataScreens=Replace` this REST page keeps its code but not its `@page` line, because the OData page has its route.
- The REST output is byte for byte what it was when `Auth` and `OData` are off.

## Guarded columns

With `ApiAuth=true` and `GuardedColumns` naming a column of this table, `OnInitializedAsync` calls `Client.GetGuardsAsync()` (`GET <route>/guards`) and the form shows that column as its input only for a person who may change it; everyone else sees the value as text (Yes / No for a flag) with the reason ("Only a manager can change this."). The stamp columns are text and say "not recorded" on a row from before they existed. The OData page asks through `<Table>ODataClient`, which reads the table's REST route. Without a guard the page has none of this code.

## The Columns list

The grid starts with the columns `GridColumns` picks and offers every column of the form in a **Columns** button above it (a native `<details>` of check boxes and a **Reset**): the key and a credential are never offered, a long-text column is offered but not shown at first, and the last shown column cannot be cleared. Which columns are offered and shown first is `ChosenGridColumns` in Core, the one rule the React and Angular grids also read.

- The choice is kept in the browser (localStorage, `<project>.columns.<page>`, a JSON list of names) by `GridColumns` (`Services/GridColumns.cs`, `BLZ_GridColumns`): a name the table no longer has is dropped, the table's order wins, and a value that is not a list of names is ignored.
- Every header, filter cell and cell is written as `@if (Shown("Name")) { ... }`, so a hidden column draws nothing. A long or multi-line text cell shows its first 60 characters (`GridColumns.Cut`).
- A sort on a column that is then hidden is dropped, and so is a filter typed for it (the OData page reads again with what is left).
- **OData:** the page asks (`$select`) for the shown columns and the key and reads again when the choice changes. **REST:** rows are whole, so a column that is shown costs no call; the server sorts by every column that is not long text or binary (`SearchSort`), so a column the grid did not start with can sort too.


## Type-ahead for a big parent

A parent with more rows than `TypeAheadRows` (default 1000, read from the database when the schema is read) or listed in `TypeAheadParents` is not read whole. The form field and the search-key filter are `<TypeAhead>` (`Components/TypeAhead.razor`), which asks `<Parent>Client.GetLookupAsync(search:)` after a pause and lists the matches. The parent's lookup list then holds only the rows the page has seen: the names of the rows of the page (`GetLookupAsync(ids:)` after each load) and the rows a person picked. The OData page does the same, in the form and in the filter row's parent column (the key picked is sent as an `eq` condition).
The rule is `FormParent.TypeAhead` in Core, the same for every stack; `TypeAheadRows=0` turns the automatic choice off. The API answers `GET <route>/lookup?search=text&take=10` (the first rows whose lookup text contains it) and `GET <route>/lookup?ids=1,2` (the names of those keys): see API_EssentialCrudApi.

A child grid that shows a name from a parent with too many rows does not read the parent whole: its lookup list is a cache, and `Know<Field>Async` asks `GetLookupAsync(ids:)` for the keys the child rows hold, each time the rows are loaded.
- **Only what changed is checked** (with `ApiAnnotations=true`). The `EditForm` is `novalidate` and carries `StoredValueValidator` (`Components/StoredValueValidator.cs`, from BLZ_EssentialSupport) instead of `DataAnnotationsValidator`: it runs the model's attributes and drops the messages of a property that still holds the value of `stored`, a copy of the row taken when it opened (none on a new row). An old email without an @ in a field left alone does not stop the save; a changed one shows `The Billing Email Address field is not a valid e-mail address.` in the page and sends nothing. Without `ApiAnnotations` the browser's own checks stay (the page has no attributes to run), but a box with a shape (`type="email"`, `tel`, `url`, or a `pattern`) carries it only while it differs from `stored` (`type="@(stored is null || row.Email != stored.Email ? "email" : "text")"`; a new row always): an old bad email in a field left alone does not stop the save, a changed one gets the browser's message. The page keeps `stored` for this too.

**Dates in order.** The end date box of a pair (`DatePairs`, see CS_Validator_v1) has `min` set to the start date; the browser refuses a Save with an end before it. The Blazor form has no check for a stored value, so an old row that already breaks the pair is refused on Save until it is fixed.

**Single-row tables.** A table the project lists in `SingleRowTables` (and does not serve as OData) gets this page as a form: the first row (`GetPageAsync(1, 1)`) opens in the editor on the page, an empty table opens a blank one, Save saves and reads the row again, and Reload reads it again. There is no grid, search, paging, Columns list, Add New, Clone or Delete, and the child grids are not shown. BLZ_Test writes the heading, the blank form and the form of one row for it.

**Name and IsActive tables.** A table with a NOT NULL `Name` and a NOT NULL `IsActive` column (its API is the `NameActiveCrudApi`: the whole list, no search, no paging) gets a page that reads the whole list (`GetAllAsync`) and narrows it with a name box and an Active only check box, without another call. It has no sort, no Columns list, no paging, no Clone and no OData page (with `ODataScreens=Replace` its REST page keeps its route), and its child tables show read-only. A 409 on Save says `A <table> with this name already exists!`. Only a table the Screens setting lists gets a page. BLZ_Test checks the name box, the conflict and the delete.

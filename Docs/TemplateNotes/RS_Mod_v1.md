# RS_Mod_v1

`src/models/mod.rs`, `src/repos/mod.rs`, `src/routes/mod.rs` and (with `ApiValidation=true`) `src/validation/mod.rs`: the module lists of the crate and the router that merges the router of every table. A new table is a regenerate; `main.rs` lists nothing. The tables are those that have an API (a single int, uniqueidentifier or text key, not a name/active table, not an enum).

The essentials add the files no table drives: `Cargo.toml` (the dependencies pinned to the versions this release was built with, in one place; the sqlx features of the project's `DatabaseProvider`), `.env.example` (the variables the API reads, no password), `.gitignore`, `src/lib.rs` (the router over a pool, CORS for the front ends' dev servers, `/openapi.yaml` when `ApiDocs=true`, the built front end from `FRONTEND_DIR`, `run()`), `src/main.rs` (calls `run()`; the library lets a desktop shell embed the same router) and `src/support.rs` (the pool type, the connection, `ApiError`, the JSON forms of dates, the LIKE escape). They are written once and kept, because they are edited by hand afterwards (`codegen essentials --stack rust`, groups `Cargo` and `Main`).

- **Connection:** PostgreSQL reads `DATABASE_URL`, else `PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE` (defaults from the project) and `PGPASSWORD`; MySQL reads `DATABASE_URL`, else `MYSQL_HOST`, `MYSQL_TCP_PORT`, `MYSQL_USER`, `MYSQL_DATABASE` and `MYSQL_PWD`; SQLite reads `DATABASE_URL` or `DATABASE_FILE` (default `DatabaseName`, relative to the folder the API runs from; a missing file is an error, not a new empty database). A `.env` file next to `Cargo.toml` is optional. No password is ever written.
- **Build:** `cargo check` and `cargo test` are the default build and test commands (`BuildRust`, `TestRust` override). On Windows `cargo` needs the Visual Studio C++ build tools in its environment; an installation without the complete library folder fails with LNK1104 (msvcrt.lib), and `Test-RustBuild.ps1` picks one that has the libraries.

## The desktop shell (essentials group `Tauri`, optional)

`desktop/` (`Cargo.toml`, `build.rs`, `tauri.conf.json`, `capabilities/default.json`, `src/main.rs`), written by `codegen essentials --stack rust --groups Tauri` (not ticked by default). A Tauri 2 shell that depends on the API crate, starts the generated API inside the app on a free local port, serves the built front end from that same port (so the React or Angular front end's relative `/api` calls need no change) and opens a window on it: one desktop app for Windows, macOS and Linux, without WinUI 3. Run it from `desktop/` with `cargo run`; the database comes from the same environment or `.env` as the API. The front end is the React `dist` folder, or Angular's `dist/frontend/browser`, under `OutputReact` / `OutputAngular` (override with `FRONTEND_DIR`). `build.rs` writes a plain placeholder `icons/icon.ico` when there is none (tauri-build needs one on Windows). Installer packaging (`bundle.active`) is not set up. Needs WebView2 on Windows (present on Windows 11).

**Checked:** the shell generated for the PostgreSQL sample compiled, started, served the unchanged React front end, and a customer was added through the form in its window (driven through the WebView2 DevTools port) and removed again.

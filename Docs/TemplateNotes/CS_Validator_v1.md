# CS_Validator_v1

A FluentValidation validator for the table's entity: `<Table>Validator : AbstractValidator<Entity>`.

- **Rules:** text that cannot be NULL is `NotEmpty()`; text has its `MaximumLength` (a Unicode column's byte length halved); a whole number keeps to the range its name suggests or its CHECK constraint states (`InclusiveBetween`; a `smallint` / `tinyint` literal is typed `(short)` / `(byte)` so the call infers); a decimal keeps to its CHECK range (`GreaterThan` for a strict bound); a column with a CHECK list gets a `Must(...)` over a static array of the allowed values; a text column named `*Email*` gets `EmailAddress()`, `*Phone*` / `*Fax*` a `Matches` of digits and punctuation, `*Url*` / `*Website*` a `Must` over `Uri.IsWellFormedUriString`; a decimal named `*Latitude*` / `*Longitude*` its degrees.
- **No rule** for identity, computed, audit, create or modify columns (the database or the repository sets them) or foreign keys.
- **The consumer is yours:** register the validators (`AddValidatorsFromAssemblyContaining<...>()`) and call them from an endpoint filter, the repository or a form. Unlike the `[Required]` / `[StringLength]` attributes of `CS_Validation`, nothing runs them for you. Needs the FluentValidation package and the entity class (`CS_Entity`), so a primary key.
- Namespace: `ValidatorNamespace` (default `<ProjectName>.App.Validators`); the entity's is `EntityNamespace`.
- **Checked:** the validators of six PostgreSQL sample tables compile against the sample's entities with FluentValidation 12; a bad customer is refused with five messages and a good one passes.
- **The consumer:** `ApiValidation=true` adds the template to a plan, makes the API essentials write `ValidationFilter.cs` (an `IEndpointFilter` that runs `IValidator<T>` and answers `Results.ValidationProblem` with the messages) and register the validators (`AddValidatorsFromAssemblyContaining<Program>()`, with the `FluentValidation.DependencyInjectionExtensions` package), and makes `API_Crud` add `.AddEndpointFilter<ValidationFilter<Entity>>()` to the create and update endpoints. **Checked** on a generated project: an empty name, a bad email and a negative credit limit gave a 400 listing the three messages; rows from `CS_Faker` were accepted.

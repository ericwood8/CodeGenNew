# UNO_Client_v1

`Services/<Table>Client.cs`: the class the Uno screens read and write a table through. A class over the app's `HttpClient` (its `BaseAddress` is the API) with `GetAllAsync`, `GetLookupAsync` (the key and display text of the rows, `GET /api/<table>s/lookup`, with `search`, `ids` and `take` for a type-ahead), `GetAsync`, `CreateAsync`, `UpdateAsync`, `DeleteAsync`, `CloneAsync` (a table `CloneShape` allows) and `GetPageAsync(page, pageSize, filters, sortBy, descending)`, which calls `/api/<table>s/search` with `pageNumber`, `pageSize`, the non-blank filters, `sortBy` and `sortDir`. They are the Blazor client's calls (`BLZ_Client`): the same API, the same JSON.

A call that does not succeed throws `ApiException` with the HTTP status (`Services/ApiSupport.cs`, the `Support` essentials group); `Explain(action)` gives the sentence a screen shows. `ApiClients` (`UNO_Screens`) holds one client per table over one `HttpClient`. The key parameter follows the key (`int`, `long`, `Guid` or `string`); a text key is escaped into the path with `Uri.EscapeDataString`. Same table rules as `UNO_Model`. With `ApiAuth=true` and a `GuardedColumns` rule that names this table the client also has `GetGuardsAsync()` (`GET <route>/guards`, the guarded columns the signed-in person may change, by JSON name). See `UNO_Screens_v1.md` for the whole stack.

# API_Csv_v1

`Apis/Csv.cs`: CSV export and import for every table that has an API of its own (any key: a text key is exported and read like any other column; a duplicate key makes the whole import refuse), with no package. Whole-database. Opt in with `ApiCsv=true` (the plan writes the file and `Program.cs` calls `app.MapCsvEndpoints()`) or `PlanAlso=API_Csv` (then add the call yourself).

- **Export:** `GET /api/<table>/export.csv` returns every row as `text/csv` (`<table>.csv`): a header line of the property names, RFC 4180 quoting, UTF-8, dates as `2026-01-15T00:00:00`, yes / no as `true` / `false`, numbers without a culture. Binary columns are left out.
- **Import:** `POST /api/<table>/import` reads a CSV body (`text/csv`, or the first file of a multipart form such as `curl -F file=@rows.csv`) and adds the rows. The first line names the columns, in any order and case; every column that cannot be NULL (apart from identity and computed columns, which are not read) has to be there. A cell that does not convert (a number, a date, a yes / no, a GUID), an empty required value, or a text longer than its column is reported by row number. With `ApiValidation=true` the table's FluentValidation validator runs on each row too. **All or nothing:** with any problem the answer is 400 `{ "imported": 0, "errors": [...] }` and nothing is saved; a database refusal (a missing parent row, a duplicate unique value) is also a 400 with nothing saved; otherwise `{ "imported": n }`. At most 10000 rows an import. The import only adds rows (no update, no upsert).
- **Spreadsheet formulas:** a text cell that starts with `=`, `+`, `-` or `@` is exported with a leading apostrophe so a spreadsheet does not run it; the apostrophe is dropped again on import.
- **No authorization:** like the other generated endpoints, these have none. Add it (or leave the flag off) before the API is reachable by anyone who should not read or add whole tables.

The conversion is reflection over the entity's properties, driven by a column list written per table (`CsvColumn`), so the generated file is small and a new column is a regenerate.

**Checked:** generated for the PostgreSQL InvoiceSystem sample, compiled and run: export of 52 customers; an import of two rows (added); rows with a bad number, yes / no and date (three errors by row); a file with columns missing (five errors); a row with a missing parent (nothing imported); a multipart upload; the added rows were deleted again.

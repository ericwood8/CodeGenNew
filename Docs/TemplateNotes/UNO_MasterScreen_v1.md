# UNO_MasterScreen_v1

The Uno twin of `WinUI3_MasterScreen` (see `WinUI3_MasterScreen_v1.md`): `Views/<Table>ListPage.xaml` and `.xaml.cs`, `ViewModels/<Table>ListViewModel.cs`. `PaginationBar` and `GridSortStore` come from the `Controls` essentials group (`UNO_EssentialControls`). The XAML is the WinUI 3 page's. The view model reads through the table's client (`UNO_Client`): `GetPageAsync` for the rows (filters by the names the API's search endpoint reads, the sort column and direction, paging), `GetLookupAsync` for the parents' names (the whole list for a drop-down, only the keys the page shows, by `ids`, for a parent with too many rows) and `GetAsync`, `DeleteAsync` and `CloneAsync` for the row buttons.

A call that fails does not throw into the page: `LoadAsync` puts the sentence in `ErrorMessage` (the page's error bar) and marks the page as loaded. Delete shows "This row cannot be deleted because it is in use." for a 400 and "This row no longer exists." for a 404. Clone opens the copy the API returns in the edit dialog.

Add and Edit open `UNO_DetailScreen`'s dialog, or `UNO_DetailMasterScreen`'s for a table that has child tables. With `Auth=true` Add New and the Edit, Clone and Delete buttons show only to the roles `WriteRoles` names for the table. Run with `Variant=OData` the template is `UNO_ODataPage` (`UNO_ODataPage_v1.md`). The page takes `ApiClients`, not an EF context. See `UNO_Screens_v1.md` for the whole stack.

**Name and IsActive tables.** A table with a NOT NULL `Name` and a NOT NULL `IsActive` column gets the page too. Its API has no search and no paging, so its client (`UNO_Client`) reads the whole list and `GetPageAsync` narrows, sorts and pages it in the client: the search boxes keep the rows whose text contains the value, a parent drop-down the rows with that key, and the Active only check box (`isActive` = `true`) the active rows. There is no Clone button and no OData page; a foreign key column sorts by its key. The dialogs say `A <table> with this name already exists.` for a 409. Only a table the Screens setting lists gets a page.

**Columns menu.** The header is built in code for the shown columns (`BuildHeader`), and the row draws their texts in `GridCells`. The Columns button beside Refresh lists every column of the form (`ChosenGridColumns`, the same rule as the web) with a check mark; the grid starts with the columns `GridColumns` picks, and the choice is kept between runs (`GridColumnStore`, `GridColumns.json`; Reset forgets it). A long or multi-line text is offered and shows its first 60 characters. Hiding the sorted column drops the sort. The text of the members is `DesktopGridColumns` in Core.

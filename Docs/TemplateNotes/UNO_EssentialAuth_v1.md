# UNO_EssentialAuth_v1

The sign-in of the Uno app: the `Auth` essentials group (`Services/AuthSession.cs`, `Views/LoginPage.xaml` and `.xaml.cs`), ticked by `Auth=true`. The API half is `ApiAuth=true` (the `Jwt` group): `POST /api/auth/login` answers `{ token, expiresUtc, user: { name, role, ownerId } }` from the ASP.NET, Python and Rust APIs.

- **`AuthSession`** holds the token and user in memory (the sign-in ends with the app), with `LoginAsync`, `Logout`, `HasRole` and a `Changed` event; **`AuthHandler`** is a `DelegatingHandler` that sends `Authorization: Bearer <token>` with every call and signs the person out when the API answers 401 to a call that carried one; **`LoginPage`** is the sign-in page with the sentences "The user name or password is not right." (401), "Too many tries. Wait a minute and try again." (429) and "Could not sign in right now.".
- With `Auth=true` the other templates change: `MainPage.xaml(.cs)` (the `App` group) shows the sign-in page until someone is signed in, then the menu of the screens the role may read, a Sign out button in the pane; `MainPage.Screens.cs` (`UNO_Screens`) lists each screen with the roles that may read it (`ReadRoles`, `TableReadRoles`); `ApiClients` takes the session; and the list pages hide Add New, Edit, Clone and Delete from a role `WriteRoles` / `TableWriteRoles` do not name (the API refuses them anyway).
- **Guarded columns** (`GuardedColumns`): `UNO_Client` gets `GetGuardsAsync()` (`GET <route>/guards`) and the detail dialogs wrap a guarded field in a panel that is enabled only when the API says the signed-in person may change it, with the guard's sentence under it when not.

Limits: the session is not kept between runs (no token on disk); no owner scoping in the screens (the API applies it); the guard stamp columns (`stampBy`, `stampOn`) show as the dialog's read-only text without the "not recorded" words of the web stacks.

**Checked** (2026-10-18): the SQL Server InvoiceSystem sample over `InvoiceSystem_test` with the generated API (users from the Employee table): the sign-in page, a wrong password refused with the sentence, a non-administrator signed in and shown the screens without the write buttons, an administrator shown them; `GET customers/guards` answered `false` for a non-manager and `true` for a manager, and the dialog showed the Credit Limit field with "Only a manager can change this." for the non-manager.

**Tenant drop-down.** With `TenantTable` and `TenantMembership` `Views/LoginPage.xaml` has a Tenant drop-down (a `ComboBox` of `SignInTenant`: the person picks a tenant by name; `AuthSession.SignInTenantsAsync` reads the list). The names come from `GET /api/auth/sign-in-tenants` (no sign-in needed: the tenants that are active and not marked deleted, by name); the first entry is blank and means the person's first tenant; when the list cannot be read the drop-down holds only the blank entry. `AuthSession.LoginAsync(http, userName, password, tenantId)` posts the `tenantId` only when a tenant is picked, and a 403 says the person is not a member of that tenant or it is switched off (`TenantWords`). 

**Tenant name and switcher.** With the same two settings `AuthSession` has `TenantsAsync(http)` (`GET api/auth/tenants`: the tenants of the signed-in person, none when the API has no such route) and `SwitchTenantAsync(http, tenantId)` (`POST api/auth/switch-tenant`: keeps the new token and raises `Changed`), and `SessionUser` carries the `TenantId`. The pane footer of `MainPage` (`UNO_EssentialApp`) shows the tenant's name for a person in one tenant and a drop-down for a person in several; choosing another makes the menu and the first screen again, so every screen reads the rows of the new tenant. The WinUI3 app has no sign-in, so it has no switcher.

# PY_Dashboard_v1

`app/routes/dashboard.py`: the dashboard's endpoint for the Python stack, written only for a project with `Dashboard=true` (the default). It is `RS_Dashboard` in FastAPI.

- `GET /api/dashboard` answers every widget of the dashboard page in one call, with the JSON the other stacks answer (`DashboardWire`): `{ "widgets": [ { "id", "kind", "title", "table", "route", "isMoney", "points": [ { "label", "value" } ], "rows": [ { "label", "detail" } ] } ] }`. `GET /api/dashboard?table=Customer` answers the cards of that table's strip (`DashboardStrip=true`); a table with none gets an empty list without touching the cache.
- The widgets and their statements are the choice `DashboardPlan` makes in Core, the one `CS_Dashboard` writes into `DashboardData.cs` and `RS_Dashboard` into `dashboard.rs`, so every stack shows the same numbers. Each statement is one fixed text without a parameter (written with `DialectInfo` for SQL Server, PostgreSQL, MySQL or SQLite) that returns two columns: a label and a value, or for a recent-rows widget a label and a detail. They run through SQLAlchemy `text()` on the same session the other routes use (`get_session`), and a colon in a statement is written `\:` so it is not read as a bind parameter. The `table` in the query string is only compared with the fixed list.
- With `ApiAuth` and `ReadRoles` or `TableReadRoles`, the handler takes the signed-in `CurrentUser` and drops the widgets of tables the role may not read from its copy of the answer (the cache is shared by every caller); the router sits behind `require_user` like the others.
- The answer is kept for a minute per table (a dictionary and a lock in the module). `PY_Mod` lists `dashboard.router` with the tables' routers, so `main.py` includes it.
- The aggregates are those of every row; a project with row-level rules must put this route behind the same policy as its tables.
- **Checked:** the InvoiceSystemPython sample was run against the SQL Server InvoiceSystem: the 11 widgets equal the ASP.NET API's answer (same ids, order, titles, routes, points and rows), and the React dashboard page draws 4 cards and 7 panels from it. With three real sign-ins (`Docs/Verification/Test-PythonDashboard.py`, 17 checks on a SQLite API with `TableReadRoles=TimeSheet:Manager`) the administrator and the manager see the TimeSheet widgets and the employee does not, also when the answer comes from the cache, and the employee's strip of that table is empty.

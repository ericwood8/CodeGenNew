FIXED:
1) Templates dialog was capped at ContentDialog's default ~550px width; now lifted
(ContentDialogMaxWidth) and the columns sized to fit, so both checkbox labels and
all the buttons are fully visible.
2) The row is wrapped in a horizontal ScrollViewer, so a window narrower than the
row scrolls sideways instead of clipping. (WinUI draws that scrollbar as a thin
auto-hiding overlay; use the mouse wheel with Shift, a touchpad, or drag its edge.)
3) The Edit button was there but sat in the clipped area. Now visible under a new
"Actions" header, with a hint line above the list, and double-clicking a row also
opens it in your editor.
4) Output Location dialog and its path field are wider (the full default path fits).
5) Could not reproduce "not saved at all": Connect -> Save persisted, and the
dialog repopulated on the next launch, with both the new and the older executable.
FOUND AND FIXED a real way to lose it: every save wrote the whole in-memory
settings back, so any other running (or stale) instance that saved ANYTHING -- even
just the Output Location -- overwrote your saved connection with its own stale
copy. Reproduced with the old code (ERICSMINIPC reverted to the stale value), gone
with the new. Saves now re-read Settings.json and change only what they own. A
connection that tested OK is also remembered if you then Cancel, and a failed
settings write is now reported in the status bar instead of silently ignored.
If it still forgets, check %LocalAppData%\CodeGenNew\Settings.json right after
connecting and tell me what LastConnection contains.
6) Every icon was blank: the embedded PNGs were copied through an unflushed stream
adapter, so the decoder was handed an empty stream. Now written with a DataWriter.
Also fixed "table.png" matching "database_table.png" (wrong table icon).
